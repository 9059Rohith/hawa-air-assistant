## Testing and efficiency follow-up

- Added independent contract boundaries for household numbers, enums, flags, coordinates, manual readings and public share payloads. Added 50-caller burst, capacity, failure cleanup, token-window and per-retry reservation tests.
- Added browser flows for validation focus, persisted preferences, unavailable storage, shared-kit validation, exported action/impact consistency, unavailable/malformed plan responses and keyboard escape/skip navigation.
- A successful but malformed HTTP plan now triggers local fallback. Clearing data or changing household inputs cancels pending work; late responses cannot resurrect the cleared plan. Clearing live state works even when browser storage throws.
- Server single-flight work is bounded to 32 distinct requests per service. Token reservations use UTF-8 payload bytes plus framing and maximum output; they are conservative estimates, not measured provider usage. The default 24,000-token rolling minute limit is per isolate, not account-wide.
- Initial JavaScript has a stricter 117,500-byte gzip gate, below Challenge 5’s recorded 117,650-byte bundle. Public checks fetch the actual deployed script bodies.

## What the preceding review fixed

- Short questions such as `mask?`, `ｍａｓｋ？` and `मास्क?` now retrieve cited guidance. Punctuation and compatibility characters are normalised, repeated query words are deduplicated, and the knowledge search text is indexed once.
- Stopping chat cancels its stream reader. A late fetch or cancelled stream cannot replace a newer reply or enter conversation history. Unmount cancels outstanding work.
- Recognised urgent phrases are handled immediately on the device, including typographic apostrophes, without waiting for an AI request. This remains conservative phrase triage, not diagnosis.
- Output guards detect Unicode numbers and zero-width/full-width obfuscation. These are tested defensive layers, not proof against every prompt injection or unsafe sentence.
- Plans omit unavailable transit, work-from-home actions with zero allowed days, and carpool suggestions for non-car travel.
- Overall coverage gates require 90% lines, 85% statements, 80% branches and 80% functions; the domain retains 100% gates across all four metrics. CI's existing coverage command also executes the scenario evaluation and fails on any failed case.

## Reproduction and limits

Run `npm run test:coverage` and `npm run eval`. `reports/scenarios.json` records every case, individual checks, source revision and whether the working tree was dirty. It is an offline acceptance result, not an LLM judge score. Read [the quality report](QUALITY_REPORT.md) for final production checks and dated performance evidence.

The GitHub account billing lock still prevents hosted CI execution. Model budget and rate limits are process-local, not distributed account-wide controls. Human screen-reader testing, independent medical validation and real-model statistical evaluation remain outside the evidence collected here. The owner-supplied LinkedIn URL was checked and opens a CarbonWise post, so it must be replaced with a HAWA post before submitting this project.

## Application-wide maintainability follow-up

The remaining eight complexity findings in the version-11 audit are resolved without suppressing lint: informational sections, purifier sizing, community input/scenario/clipboard controls, profile fields, plan headings and plan-request lifecycle have focused owners. The same complexity threshold now fails lint across all application source. The 486 Vitest cases include 399 unit/component/API/contract regressions and 87 acceptance scenarios. This is repository evidence, not a predicted competition score.
